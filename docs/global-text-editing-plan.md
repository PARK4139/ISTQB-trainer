# 메모 DB 통합과 웹 전체 문구 즉시 편집 계획

## 사용자 스토리

학습자로서 고급설정의 웹 전체 편집을 켜고 문구를 선택한 뒤 Ctrl+Shift+L을 눌러, 메모와 숨겨진 탭까지 같은 문구를 동시에 수정하고 싶다. 변경은 입력 즉시 보이고, 저장·복구·이력과 Git 비교를 통해 관리할 수 있어야 한다. 미리보기나 별도 적용 버튼은 두지 않는다.

## 현재 구조와 변경 방향

현재 UI는 `content/locales.sqlite`, 학습 데이터는 `web/index.html`, Google 답변은 `content/google-ai-answers.json`, 메모는 `notes/study-notes.md`에 저장된다. 브라우저는 메모를 먼저 편집하고 로컬 서버로 비동기 저장한다.

기존 SQLite를 확장해 콘텐츠와 메모의 저장 기준으로 삼는다. UI 번역, 구조화된 문구, 메모, 변경 묶음과 버전을 분리한다. 문구의 ID는 문구 값이 바뀌어도 유지한다. DB를 DOM 텍스트나 HTML 코드 전체의 문자열 치환으로 수정하지 않는다.

메모 API의 응답 구조와 브라우저 로컬 백업은 유지해 전환 영향을 줄인다. 기존 Markdown·JSON·HTML은 백업·검증 후 한 번만 가져오며 재실행으로 최신 DB를 덮어쓰지 않는다. 서로 다른 원본이 발견되면 자동 덮어쓰기 대신 충돌로 보존한다. 학습 진도·응답 상태는 이번 DB 통합 대상에서 제외한다.

## 편집 동작

1. 고급설정 기본값은 OFF다. OFF에서 기존 메모 Ctrl+Shift+L 동작을 유지한다.
2. ON에서 메모 또는 학습 웹의 문구를 선택하고 Ctrl+Shift+L을 누르면 전체 편집 세션을 시작한다. 텍스트 입력 컨트롤에서도 선택을 읽을 수 있어야 한다.
3. 정확한 문자열과 대소문자 일치로 원본 문구 레코드·발생 위치를 검색하고 대상 ID·범위·버전을 고정한다. 같은 키가 여러 화면에 렌더링돼도 원본 레코드를 중복 수정하지 않는다.
4. 현재 화면의 일치 위치와 전체 대상 수·위치를 표시한다. 숨겨진 탭도 포함하되 코드·ID·URL·파일 경로·수식 구조·정답 인덱스·출처 메타데이터는 제외한다.
5. 기존 CodeMirror를 편집 입력에 활용해 입력·삭제·붙여넣기·다중 커서·IME를 처리한다. 선택된 모든 발생 위치가 입력 즉시 바뀌며 별도 미리보기·적용 버튼은 없다. 입력 중 대상 집합을 새로 검색하지 않는다.
6. 화면은 변경된 부분만 갱신한다. 포커스, 선택, 스크롤과 시험 진행 상태를 보존한다. Esc로 세션을 종료하며 이미 입력한 내용은 유지한다.

## 저장·복구·Git

- 목표 저장 지연은 마지막 입력 후 400ms다. 조합 입력 도중에는 저장을 확정하지 않는다. 저장 중 다음 입력이 오면 최신 초안을 별도 대기시켜 오래된 응답이 덮어쓰지 못하게 한다.
- 한 묶음은 SQLite 트랜잭션으로 저장하며 대상 버전을 함께 검사한다. 하나라도 충돌하면 그 묶음 전체를 취소하고 초안을 보존한다.
- 화면 즉시 반영과 저장 완료는 구분해 `저장 중 / 저장됨 / 저장 실패 / 충돌`을 표시한다. 설정 OFF·탭 숨김·종료 전에 저장을 시도하고, 전송 성공을 보장할 수 없는 종료는 로컬 복구 초안으로 보완한다.
- Ctrl+Z/Ctrl+Y는 편집 세션 내 전체 대상을 하나의 묶음으로 취급한다. 서버 변경 이력에는 이전·이후 값과 대상 ID·버전·시간을 기록한다. 다른 변경 이후 복원도 버전을 검사한다.
- DB 저장 트랜잭션과 파일 출력은 하나의 원자 작업이라고 주장하지 않는다. DB 안에 내보내기 대기 버전을 기록하고 출력 파일을 임시 파일에서 교체한다. 중단 시 최신 커밋 버전으로 재시도한다.
- Git 검토용 콘텐츠 JSON과 메모 Markdown은 일정한 순서·형식으로 출력한다. DB가 유일한 실행 기준이며 출력 파일의 외부 수정은 해시로 감지한다. 자동 커밋·push는 하지 않는다.
- 일반 메모 저장은 메모 Markdown 출력만 갱신한다. UI·학습 콘텐츠가 변하지 않았으면 HTML 전체 빌드를 실행하지 않는다. 오프라인 배포 HTML은 관련 콘텐츠 변경 때 갱신한다.
- 공식 샘플과 Google 답변은 최초 원문·출처·버전을 보존하고 사용자 수정본을 별도 오버라이드로 둔다. 화면과 내보내기에서 수정 여부를 구분한다.
- 브라우저가 DB를 직접 열지 않고 기존 로컬 Node 서버만 접근한다. 같은 출처 검사·요청 크기 제한·버전 충돌 검사를 유지한다. file:// 배포본은 저장 가능한 서버와 연결되지 않으면 편집 기능을 활성화하지 않는다.

## 성능 판정 계획

현재 구현과 전환 후를 동일 PC·브라우저·화면 폭에서 각각 워밍업 후 5회 측정한다. 일반 메모는 현재 크기와 100KB, 전체 편집은 실제 콘텐츠 전체와 1,000개 일치 위치를 사용한다. 한국어 IME·연속 입력·붙여넣기·Ctrl+D·Ctrl+Shift+L·감싸기·실행 취소·저장 중 입력을 포함한다.

입력에서 다음 화면 반영까지 p95 100ms 이하를 목표로 하고, 일반 메모의 baseline 대비 p95 증가는 10ms 이하를 목표로 한다. 2초 이상 연속 입력 종료 후 로컬 DB 저장 응답은 p95 500ms 이하를 목표로 한다. 400ms debounce와 Git 출력·HTML 빌드 시간은 별도 기록한다. 기준을 넘으면 원인을 기록하고 관련 Issue를 완료하지 않는다. 이 수치는 아직 실측 결과가 아니다.

검증 시 실제 사용자 DB·메모를 변경하지 않고 임시 복제본을 쓴다. 증거는 지정 규칙의 `{D_TEMP}/evidence/istqb/verification/{issue-id}/`와 `E_{issue-id}.md`에 저장한다. 서버 재시작·다중 창 충돌·저장 실패·이관 재실행·내보내기 중단 복구를 포함한다.
