# 요구사항 출처

- 범위: ISTQB 학습 웹의 메모 SQLite 통합과 고급설정 기반 웹 전체 문구 즉시 편집.
- 근거: 2026-10-15 현재 대화에서 사용자가 제시하고 확인한 요구사항.
- 등록 권한: “ok, do make plan and do issue (3rd_party\pk_system\cores\common\rules 의 issue 관리 규칙을 따라라)”.
- 관리 규칙: `../../../3rd_party/pk_system/cores/common/rules/issue/lifecycle.py` 및 `issue_verification_artifact_location.py`.
- 이 저장소에는 기존 handover/showreel 또는 Issue 큐가 없어 아래 요구사항 ID를 이 대화의 추적 기준으로 사용한다.
- 구현 계획: [웹 전체 문구 편집 계획](../docs/global-text-editing-plan.md).

| ID | 사용자 요구사항 |
|---|---|
| FR-01 | 학습 메모를 SQLite로 통합하고 기존 자료를 보존한다. |
| FR-02 | UI·학습 콘텐츠·Google 답변을 고유 ID로 관리해 전체 편집 대상에 포함한다. |
| FR-03 | DB를 기준으로 Git 검토용 텍스트와 오프라인 HTML을 생성한다. |
| FR-04 | 고급설정에서 웹 전체 편집을 ON/OFF하며 기본값은 OFF다. |
| FR-05 | ON에서 Ctrl+Shift+L은 숨겨진 탭을 포함한 전체 문구의 정확 일치를 선택하고, OFF에서는 기존 메모 선택을 유지한다. |
| FR-06 | 미리보기·적용 버튼 없이 입력 즉시 선택된 모든 문구를 수정한다. |
| FR-07 | 저장은 비동기로 묶어서 처리하고, 충돌·실패로 변경을 유실하지 않는다. |
| FR-08 | 변경 묶음의 이력을 보관하고 전체 대상을 함께 실행 취소·복원한다. |
| FR-09 | 저장 상태와 미저장 변경을 알리고 재접속 시 미저장 초안을 복구한다. |
| FR-10 | 일반 메모 입력의 현재 반응성을 유지하고 전체 편집 성능을 실측한다. |

| ID | 독립 수용 기준 |
|---|---|
| AC-01 | 메모 이관·재시작·재이관에서 기존 내용과 버전이 보존된다. |
| AC-02 | 모든 대상 문구가 안정적인 ID로 DB에서 읽히고 비문구 데이터는 제외된다. |
| AC-03 | 동일 DB의 내보내기는 결정적이며 Git 비교·재생성·오프라인 사용이 가능하다. |
| AC-04 | 설정 기본 OFF와 ON/OFF 유지가 동작하고 저장 대기 상태에서 변경을 잃지 않는다. |
| AC-05 | 전역 선택 범위가 정확하며 선택 시 고정되고 기존 메모 단축키가 보존된다. |
| AC-06 | 선택된 모든 발생 위치를 미리보기 없이 즉시 편집하고 다중 편집·IME를 유지한다. |
| AC-07 | 저장 묶음이 전부 반영되거나 전부 취소되고 버전 충돌에서 덮어쓰지 않는다. |
| AC-08 | 전역 실행 취소·다시 실행·이력 복원이 모든 대상에 일관되게 적용된다. |
| AC-09 | 종료·실패·재접속에서 미저장 변경을 보존하고 상태를 정확히 표시한다. |
| AC-10 | 정해진 데이터와 동일 환경의 전후 측정으로 입력·저장 성능을 판정한다. |
| AC-11 | 공식 자료와 수집 답변의 원문·출처를 보존하고 사용자 수정본을 구분한다. |
